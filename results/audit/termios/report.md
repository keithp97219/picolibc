# `<termios.h>` audit against POSIX.1-2024 (Issue 8)

Worktree `/local/home/keithpac/audit-termios`, branch `audit/termios`, based on
a687616faa (`claude/posix-spec-audit`). Host: AWS Graviton2, aarch64 Linux 5.10;
builds and tests ran in the Debian sid chroot (gcc 16.2, glibc 2.43) as an
unprivileged user, with `/dev/ptmx` and `/dev/pts` (devpts `gid=5,mode=620`).

Implementation: `libos/linux/` (tcgetattr.c, tcsetattr.c, tcdrain.c, tcflow.c,
tcflush.c, tcsendbreak.c, tcgetsid.c, tcgetwinsize.c, tcsetwinsize.c, cfgetispeed.c,
cfgetospeed.c, cfsetispeed.c, cfsetospeed.c, cfsetspeed.c, local-termios.h and the
per-architecture `machine/*/linux/linux-termios.h` generated by `utils/make-termios.c`;
for the related functions posix_openpt.c, grantpt.c, unlockpt.c, ptsname.c,
ptsname_r.c, isatty.c, ttyname.c, ttyname_r.c and sysconf.c). Headers:
`libc/include/termios.h` → `libc/include/sys/termios.h`; `_POSIX_VDISABLE` is in
`libos/linux/include/sys/_posix.h`.

Tests: `test/test-posix/test-termios/` unless another directory is named
(`stdlib/` = `test-posix/test-stdlib/`, `unistd/` = `test-posix/test-unistd/`). File
names drop the `test-` prefix (`tcsetattr-icanon.c` = `test-tcsetattr-icanon.c`).
Line numbers are for the branch tip.

Spec source: the pubs.opengroup.org/onlinepubs/9799919799 pages basedefs/termios.h,
basedefs/V1_chap11 (XBD 11, General Terminal Interface), functions/tcgetattr,
tcsetattr, tcdrain, tcflow, tcflush, tcsendbreak, tcgetsid, tcgetwinsize, tcsetwinsize,
cfgetispeed, cfgetospeed, cfsetispeed, cfsetospeed, posix_openpt, grantpt, unlockpt,
ptsname (covers ptsname_r), isatty, ttyname (covers ttyname_r), open (O_TTY_INIT), and
XSH 2.2.2 (reserved names) and 2.9.5.2 (cancellation points). All 13 `<termios.h>`
interfaces are in Issue 8; tcgetwinsize and tcsetwinsize are new in it.

Status key: TESTED (file:line), UNTESTED, NOT TESTABLE (reason). Every TESTED row was
run and passes for picolibc (`test-X`) and against glibc (`test-X-native`) on
aarch64-linux-gnu and arm-linux-gnueabihf, unless it says picolibc only. All
pseudo-terminal tests use `posix_openpt`. Tests that need a controlling terminal set
one up in a child after `setsid()` and exit 77 if the system won't give one. "(existing)"
marks rows that were tested before this audit.

  G14-G27, M3-M7, M9-M11, M14-M22, M24, TG1-TG4, TS1-TS3, TS5, TS7-TS11, E-TS1-E-TS3,

## Deviations found and fixed

Each fix was verified by running it on aarch64-linux-gnu. With only the library change
reversed (`git show <fix> -- libc libos | git apply -R`, rebuild, run, reapply) the new
check fails; with the fix it passes. The failing check is quoted for each.

1. **cfsetispeed(B0) stored the output speed** (libos/linux/cfsetispeed.c). POSIX:
   "cfsetispeed() shall set the input baud rate stored in the structure … to speed", and
   cfgetispeed "shall return exactly the value in the termios data structure". The
   meaning of B0 (use the output speed) belongs to tcsetattr. Failing-before:
   `cfgetispeed returns what cfsetispeed set: cfgetispeed(&t) == speeds[i]`.
2. **tcsetattr never changed the speeds** (libos/linux/tcsetattr.c, local-termios.h).
   The kernel takes the speeds from the CBAUD and CIBAUD bits of c_cflag, and reads
   termios2's c_ispeed and c_ospeed only when CBAUD is BOTHER. picolibc filled in only
   c_ispeed and c_ospeed and kept the old CBAUD bits, so after tcsetattr a pty still
   reported 38400. The speeds are now encoded as Linux's B codes, with BOTHER for
   speeds that have no code. An input speed of B0 leaves CIBAUD zero, which the kernel
   treats as "use the output speed", exactly as tcsetattr requires. The B57600 …
   B4000000 codes, CBAUD, BOTHER, CIBAUD and IBSHIFT were added to `make-termios.c` and
   to the five generated headers. The values are the same on every architecture
   picolibc has; I checked them against the generator's output here. glibc 2.43 passes
   the same test. Failing-before: `output speed set: cfgetospeed(&got) == B9600`.
3. **cfsetspeed.c defined a second cfsetospeed** (libos/linux/cfsetspeed.c), one that
   set both speeds. Which cfsetospeed a program got depended on the archive order (here
   it happened to be the right one), and cfsetspeed itself didn't exist. The function
   is now named cfsetspeed and declared under `__BSD_VISIBLE`, as glibc and the BSDs do.
   Failing-before (compile): `implicit declaration of function 'cfsetspeed'`. This is
   an extension, so its test uses `_DEFAULT_SOURCE`.
4. **The XSI delay names were visible in strict POSIX mode**
   (libc/include/sys/termios.h). NLDLY, NL0, NL1, CRDLY, CR0-CR3, TABDLY, TAB0-TAB3,
   BSDLY, BS0, BS1, FFDLY, FF0 and FF1 are XSI names outside `<termios.h>`'s reserved
   prefixes (c_, B[0-9], TC, ws_, and I, O and V for macros), so a strictly conforming
   program may use them. They are now under `__XSI_VISIBLE`. VTDLY, VT0 and VT1 moved
   with them, and the block now sits below the flow constants so clang-format doesn't
   realign the rest of the file. glibc hides them the same way. Failing-before:
   `#error XSI delay names visible without _XOPEN_SOURCE`.
5. **posix_openpt accepted O_SEARCH and O_EXEC** (libos/linux/posix_openpt.c). Its flag
   check used O_ACCMODE, which now includes them (files unit). So
   `posix_openpt(O_RDWR | O_SEARCH)` returned an O_PATH descriptor for /dev/ptmx, which
   isn't a manager. It now accepts only the three classic access modes (EINVAL is a
   "may fail"). Failing-before:
   `O_SEARCH: posix_openpt(O_RDWR | O_SEARCH) == -1 && errno == EINVAL`.
6. **ptsname_r didn't check for a null name** (libos/linux/ptsname_r.c). POSIX: "[EINVAL]
   The name argument is a null pointer" (shall fail). The pointer went straight to
   snprintf. Failing-before: the test is killed by SIGSEGV.
7. **sysconf(_SC_TTY_NAME_MAX) was 9** (libos/linux/sysconf.c). That is the POSIX
   minimum, taken from libos/fallback, but ptsname and ttyname return `/dev/pts/N`,
   which is 10 bytes or more. POSIX: "The maximum length of the terminal name shall be
   {TTY_NAME_MAX}". It now returns 32, glibc's value. Failing-before:
   `TTY_NAME_MAX: sysconf(_SC_TTY_NAME_MAX) < 0 || strlen(name) < (size_t)sysconf(_SC_TTY_NAME_MAX)`
   in both ptsname_r and ttyname_r. sysconf belongs to unistd-config; I changed only
   this value, the terminal-name limit.

## Deviations not fixed

- **O_TTY_INIT is 0, but Linux keeps a terminal's settings between uses** (O2; the files
  unit passed this note on). POSIX allows O_TTY_INIT to be zero only if open() then
  always "set[s] any non-standard termios structure terminal parameters to a state that
  provides conforming behavior" on the first open of a terminal that isn't a pty.
  Linux serial drivers save termios in the driver and restore it on the next open
  (except drivers with TTY_DRIVER_RESET_TERMIOS). So IUCLC, OLCUC, XCASE, a line
  discipline other than N_TTY and the like survive from the last user, and picolibc
  can't conform with a zero O_TTY_INIT. A fix would make O_TTY_INIT a picolibc-only
  open flag that is never passed to the kernel. When it is set and the file is a
  terminal other than a pty, open/openat would clear the Linux-only flags and set
  N_TTY. Candidates: IUCLC, OLCUC, XCASE, FLUSHO, PENDIN, EXTPROC and CMSPAR; possibly
  IMAXBEL, IUTF8 and CRTSCTS; and ECHOCTL, ECHOPRT or ECHOKE as needed. POSIX leaves it
  unspecified whether O_TTY_INIT does anything when the device is already open, so open
  wouldn't need to find that out. Which Linux flags count as non-conforming is a policy
  choice, the flag's value is an ABI change, and it couldn't be tested here (no serial
  devices), so it is left for a decision. glibc doesn't define O_TTY_INIT at all; musl
  defines it as 0.
- **Reopening a pty subsidiary keeps its old state** (O1). POSIX says opening a
  subsidiary "that is not already open in any process" resets the non-standard
  parameters and the window size, whatever O_TTY_INIT says. Linux initializes the pair
  only when the manager is opened. picolibc can't tell whether another process has the
  subsidiary open, so it can't do this safely. Kernel behaviour.
- **tcsetwinsize from a background group neither sends SIGTTOU nor fails with EIO** (G11,
  Z3; new in Issue 8). Linux's TIOCSWINSZ doesn't call tty_check_change. Emulating it
  would need another ioctl that runs the check without side effects. The candidates
  (TCSETS2 with the current settings, TIOCSETD with the current line discipline, TCSBRK)
  either race with other processes or wait for output to drain, so I left it.
- **No backslash escape of ERASE, KILL and EOF with IEXTEN** (G29, XSI). Linux offers
  LNEXT (^V) instead. Kernel behaviour.
- **The XSI output delays and fill characters do nothing** (M12). Linux stores NLDLY,
  CRDLY, TABDLY (other than TAB3), BSDLY, VTDLY, FFDLY, OFILL and OFDEL but ignores them.
  Kernel behaviour. There is no test, since only the fill characters could be observed.
- **grantpt doesn't set the group-write bit itself** (GR1). picolibc's grantpt only
  checks the descriptor and relies on devpts, which applies the mount's `mode=` option
  (620 here; the kernel default is 600). POSIX wants "readable and writable by the
  owner, and writable by the group". glibc behaves the same. `chmod("/dev/pts/N", 0620)`
  would fix it, but it would override an administrator who mounted devpts with mode=600
  to stop write(1) and wall, so I left it alone. The test checks the owner, the owner's
  read and write bits and that no extra bits are set, but not group write.
- **O_CLOFORK in posix_openpt** (P3): part of the files unit's close-on-fork gap.

## Other observations (not changed)

- glibc 2.43 differences met along the way, all handled with `#ifndef __GLIBC__` or the
  existing `__PICOLIBC__` guards: no tcgetwinsize or tcsetwinsize; `struct winsize` only
  in `<sys/ioctl.h>`; ptsname_r crashes on a null name (and declares the argument
  non-null, so the test passes it through a volatile pointer); ttyname_r returns ENODEV
  rather than ERANGE when the buffer is one byte short.
- MAX_CANON and MAX_INPUT are 255 in `<limits.h>`, while Linux's n_tty buffer holds 4096
  bytes and accepts canonical lines of up to 4095. POSIX makes the behaviour past
  MAX_CANON implementation-defined, so this is consistent; glibc uses the same 255
  (inferred).
- tcsendbreak ignores a non-zero duration and sends Linux's 0.25-0.5 s break. The length
  is implementation-defined, so this is allowed.
- tcgetattr drops the Linux flags picolibc doesn't name. tcsetattr reads the kernel's
  settings first and changes only the named flags, so the others are kept, as POSIX
  requires ("leave all the attributes not supported by the implementation unchanged").
  Inferred by reading; the settings tests rely on it.
- On Linux the manager and subsidiary have separate termios; only the window size is
  shared.
- tcdrain is the only cancellation point among the termios functions, as POSIX
  requires; the others use the non-cancelling `_syscall` (inferred by reading).
- `<termios.h>` defines more speeds than POSIX (B7200 … B10000000), all in the reserved
  B[0-9] space. Linux has no code for B7200, B14400, B28800, B33600, B76800, B153600,
  B307200, B614400, B5000000 or B10000000; those now go to the kernel as BOTHER with
  the exact rate.
